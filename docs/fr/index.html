PWA open source · auto-hébergée

Une interface de chat pour vos agents qui affiche plus que du texte.

Votre agent appelle un outil, AgentUI affiche un graphique, un tableau, une carte, un formulaire ou une progression dans le chat. Auto-hébergé, installable en PWA, sur desktop comme sur téléphone.

Les widgets

Les widgets sont des outils.

L’agent appelle un outil avec des arguments JSON, le schéma les valide, et l’interface affiche un vrai composant au lieu de Markdown.

Graphiques

Courbes, barres et camemberts.

L’agent envoie ses séries, AgentUI les trace avec Chart.js. Info-bulles, légendes, et un bouton pour copier les données.

Sur mesure

Widgets sur mesure : l’agent écrit le composant.

Quand aucun widget ne convient (simulateur, convertisseur, liste filtrable, jeu), l’agent écrit un composant React avec le même kit que les miniapps. AgentUI le compile et l’affiche dans le chat.

  • Exécuté dans un iframe isolé, sans accès à votre session
  • Mêmes composants et mêmes couleurs que les miniapps
  • Ses boutons peuvent écrire dans la conversation : « Détails », « Réserver »… l’agent reçoit la réponse comme un message
  • Pour garder l’outil, l’agent en fait une miniapp
  • Cartes interactives (Leaflet), graphiques et canvas ; si le widget plante, un clic envoie les traces à l’agent pour qu’il le corrige

agentui_widget_custom

Miniapps

Miniapps : l’agent construit ses propres outils.

Suivi de dépenses, tableau de bord, liste partagée : l’agent écrit une miniapp (un front React et des handlers côté serveur) qui apparaît dans l’onglet Miniapps.

Aux couleurs d’AgentUI

Même look que l’application.

L’agent dispose d’un kit de composants React et des variables CSS du thème : la miniapp suit le mode clair/sombre, la langue et le format mobile sans style en dur.

  • Composants prêts à l’emploi : formulaires, listes, tableaux, graphiques
  • Pensées d’abord pour le téléphone
  • Mise à jour en direct quand l’agent modifie la miniapp
agentui_miniapp_write

L’agent écrit

Il lit le guide fourni par le plugin, puis envoie ses fichiers avec des outils agentui_miniapp_*. Les erreurs de compilation lui reviennent avec le fichier et la ligne : il corrige tout seul.

AgentUI compile et isole

Le front tourne dans une iframe sandbox, sans accès à votre session. Les handlers s’exécutent dans un worker isolé, avec leurs propres données, protégés par l’authentification d’AgentUI.

La miniapp apparaît

Elle est dans l’onglet Miniapps, tout de suite. Un cron ou l’agent peut y pousser de nouvelles données : la miniapp ouverte se rafraîchit seule.

Données et API

Un petit backend par miniapp.

Chaque miniapp a ses collections et son stockage clé/valeur, isolés des autres. Les handlers peuvent appeler des API publiques ; les adresses privées et internes sont refusées.

  • Routes protégées par la session AgentUI, un espace de noms par miniapp
  • Appels HTTP sortants bornés (durée, taille, adresses publiques uniquement)
  • L’agent lit et écrit les données avec agentui_miniapp_data
Une miniapp n’accède qu’à ses propres routes et données : ni à vos conversations, ni aux autres miniapps.
Tâches planifiées

Chaque tâche cron a sa discussion.

Résumé du matin, veille, contrôle de sauvegarde… Chaque tâche cron de vos agents a sa discussion où le résultat est posté comme un message, widgets compris.

Messages de cron

Messages proactifs des crons.

À chaque exécution, l’agent poste un message dans la discussion « ⏰ nom de la tâche ». Vous pouvez y répondre et continuer à partir de là.

  • Une discussion par tâche, rangée dans la section « Tâches cron »
  • Pastille « non lu » et repère « Nouveau message »
  • Tableaux, listes et autres widgets dans le message

La tâche s’exécute

Le planificateur de la plateforme (Hermes, OpenClaw…) lance la tâche à l’heure prévue — prompt confié à l’agent, ou simple script.

Le message arrive

Le plugin le transmet à AgentUI, qui le range dans la discussion dédiée. Elle est créée automatiquement à la première exécution.

Vous êtes prévenu

Une notification push s’affiche ; un clic ouvre directement la bonne discussion, même si l’application était fermée.

Page « Tâches »

Statut et erreurs des tâches.

Planification, prochaine exécution et dernier statut sur une page. En cas d’échec, l’erreur complète est à un clic, sans fouiller les logs.

  • Statut et erreur de la dernière exécution
  • Accès direct à la discussion de la tâche
  • Pause, reprise, « Exécuter maintenant », suppression
Une tâche poste dans AgentUI quand elle est configurée pour y livrer ses résultats ; ses échecs peuvent suivre le même chemin.

Comment ça marche

Un plugin, un protocole WebSocket.

AgentUI parle à votre plateforme d’agents via un plugin canal, sur un protocole WebSocket simple, un peu comme un bot Telegram.

Installez le plugin

Plugins fournis pour Hermes et OpenClaw. La plateforme ouvre la connexion vers AgentUI — rien à exposer de son côté.

L’agent reçoit de nouveaux outils

Graphique, tableau, carte, progression, code, formulaire… déclarés comme des outils classiques avec leurs schémas JSON.

L’interface l’affiche

L’agent appelle l’outil et écrit le jeton retourné dans sa réponse. AgentUI remplace le jeton par le composant, même pendant le streaming.

// L’agent appelle un outil…
agentui_widget_chart({
  kind: "line",
  title: "Chiffre d’affaires mensuel",
  unit: " k€",
  x: ["Jan", "Fév", "Mar"],
  series: [{ name: "2026", y: [96, 103, 112] }]
})

// …et place le jeton dans sa réponse :
"Voici l’évolution : [[agentui:a3f9c1]]"

// AgentUI affiche le graphique à cet endroit.
Comparatif

Comparatif

Face aux messageries (Telegram, Discord…) et aux interfaces web qui passent par l’API (Open WebUI, Hermes WebUI…). Chacune a ses forces.

MessageriesTelegram, Discord, WhatsApp…UI web via APIOpen WebUI, Hermes WebUI…AgentUIPlugin canal + PWA
Plusieurs discussions~Topics ou threads, selon la messagerie✓Oui✓Une session distincte par discussion
Rendu riche (graphiques, tableaux, cartes, formulaires)✗Texte et boutons~Markdown, selon l’outil✓Widgets appelés comme des outils
Outils, raisonnement, sous-agents, coût✗Non affichés~Partiel, dépend de l’API✓Événements natifs du protocole
Approbations et questions en cours d’exécution~Boutons inline à bricoler✗Pas dans une API de chat✓Natifs, la discussion continue
Messages proactifs (crons, rappels)✓Oui✗Pas de canal pour l’agent✓Chat dédié « Messages de l’agent »
Pilotage des tâches planifiées et des skills✗Non~Selon l’UI : certaines le permettent✓Pause, lancement, erreurs, lecture
Notifications push sur mobile✓Excellentes, rien à configurer~Variable selon l’outil~Oui, mais HTTPS requis (iPhone : écran d’accueil)
Agent derrière un NAT✓Oui✗L’API doit être joignable✓Connexion sortante du plugin
Données sous votre contrôle✗Passent par un tiers✓Auto-hébergé✓Auto-hébergé
Mise en place✓Presque rien~Une UI à installer et à brancher~Un service + un plugin par plateforme
Maturité et communauté✓Très mûr✓Grosses communautés✗Jeune, un seul mainteneur
Indépendance vis-à-vis de la plateforme✓Bonne✓Très bonne (API standard)~Un plugin à maintenir pour Hermes, OpenClaw…

✓ bien couvert · ~ partiel ou avec réserves · ✗ absent ou peu adapté. Appréciations générales, qui varient selon l’outil et sa version.

En résumé. Pour simplement parler à un agent depuis le téléphone, une messagerie suffit et demande moins d’efforts. Pour une interface de chat généraliste ou multi-utilisateur, une UI via API est plus complète. AgentUI vise les vrais agents : outils, sous-agents, crons, approbations, widgets. Sa contrepartie : un service de plus à héberger et des plugins à maintenir.

À essayer

Lancez-le avec Docker, installez le plugin de votre plateforme, connectez.
